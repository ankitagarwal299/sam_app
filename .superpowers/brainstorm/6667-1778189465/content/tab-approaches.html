Inbound Purchase Order — Tab Structure

With the new workflow (Draft → Approved → Signed/Ignored), how should we organize the tabs?

A

Status-Based Tabs (one per workflow state)

Each tab shows POs in that state. Clear mapping to workflow.

Draft (8)
Approved (3)
Signed (5)
Ignored (2)
✅ Clear 1:1 mapping to workflow
✅ Easy to find POs by status
⚠️ 4 tabs — might feel like a lot
⚠️ "Signed" tab becomes the source for GPS & Financial Analyst
B

Action-Based Tabs (Inbox / Processed / Ignored)

Group by what needs attention vs what's done. Fewer tabs.

Inbox (11)
Processed (5)
Ignored (2)
Inbox = Draft + Approved (needs action)
Processed = Signed (done, sent to GPS & FA)
✅ Simpler — 3 tabs
✅ Status shown as column + badge in table
⚠️ Mixes Draft and Approved in one tab
C

Single Table with Status Filter (Recommended)

One table, filter by status. Status column + badges make state obvious. Cleanest.

All (18)
Draft (8)
Approved (3)
Signed (5)
Ignored (2)
✅ All POs visible at once, filter as needed
✅ Status column with colored badges
✅ Per-row actions (Approve/Sign) in Actions column
✅ Scales to any number of statuses without adding tabs
✅ Closest to your "all POs can arrive in any state" requirement

Recommendation: Option A

  • Status tabs give the clearest view of the workflow pipeline
  • Each tab has focused actions — Draft tab has "Approve" and "Ignore", Approved tab has "Sign"
  • User always knows where they are in the workflow
  • Counts on each tab serve as a mini-dashboard

Option C is good too if...

  • You expect many more statuses in the future
  • Users want to see everything in one view
  • The dataset is small enough that filtering is sufficient
